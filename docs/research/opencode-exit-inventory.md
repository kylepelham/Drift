# OpenCode exit inventory

Investigated 2026-09-29 against the checked-out sources. This is a static inventory of the **current** OpenCode implementation and its exit requirements, not a report of replacement-engine progress. No live credentials, paid model requests, or secret files were read. The untracked `docs/claude-code-binary-comparison.md` was read as contextual research and left untouched. Root `AGENTS.md:3-45` fixes the Rust replacement architecture; `docs/engine-rewrite.md` is the plan of record and `CHECKLIST.md` tracks pending milestones. Both plan files are present in the current checkout. This inventory neither supersedes them nor claims any crate is implemented.

## Decision and boundary

Build `crates/drift-engine` as a **Rust library linked into Tauri**. Its `api` module serves loopback HTTP and one WebSocket; `src/engine/` uses an OpenAPI-generated TypeScript client, WebSocket pump, and store. `crates/drift-engined` is a headless harness for remote/conformance testing, never an installed-app sidecar. `crates/drift-migrate` is the one-time OpenCode importer. Use a **bounded, temporary compatibility translator** for only the currently consumed legacy routes and SSE events inside the owned axum API during the frontend transition. It may translate ingress/egress shapes into the native domain, not own tools, permissions, credentials, compaction, storage, or a second live session writer. Its outputs feed the same owned session/event services as the new HTTP and WebSocket endpoints. Remove it and the legacy SDK after the generated client covers callers. A big-bang UI/runtime switch hides failures; a permanent OpenCode adapter violates the exit goal. No new overlays or OpenCode plugins are allowed (`AGENTS.md:10-12,16-45`; `docs/engine-rewrite.md:19-41,43-60,67-106`).

The Rust core must own session/turn admission, serial execution, durable transcript and file-change history, permission and question waits, tool execution, provider/model/auth, effective configuration, and MCP runtime. The Tauri shell retains window, remote device authentication/TLS, UI preferences, file preview, voice, notifications and updater, and links the engine. **One `drift.db` in that process has one writer for shell and engine tables**; the present shell store is a starting point, not a second runtime authority. Content-addressed attachments and seven-day archive purge remain product invariants. The UI retains presentation and view state; engine extension points are internal Rust `Hook` traits, with no JavaScript host or arbitrary OpenCode JS plugin execution. Existing Drift UI hooks may stay UI-side and cannot become an engine plugin host. The UI must not be the authoritative turn scheduler. Current behavior is documented separately in `docs/architecture.md:3-51`, `src/engine/actions.ts:74-98`, `src-tauri/src/main.rs:172-243`.

## Runtime topology and actual paths

1. `scripts/build-engine.ts:7-24` applies overlays and invokes upstream's Bun build; `scripts/build-extensions.ts:8-70` bundles three OpenCode plugins, optional tool router, and a prompt catalog extracted from upstream text. `src-tauri/tauri.conf.json:56-66` bundles the sidecar, extension files, and OpenCode license. `scripts/dev.ts:8-65` launches a separate local dev server with an ephemeral policy. `scripts/test-engine.ts:65-148` is the curated patched-upstream test runner. Build replacement must remove overlay application and upstream build/update automation only after parity gates pass.
2. **Current implementation only:** native startup materializes generated `opencode.json`, MCP approval policy, and prompt overrides before the sidecar (`src-tauri/src/main.rs:177-210`, `src-tauri/src/mcp.rs:115-211`). `src-tauri/src/engine.rs:161-349` launches `serve` on loopback port zero with a per-run Basic password, `OPENCODE_CONFIG_DIR`, required approval flag, optional router module and shared-DB flag. It parses the URL from stdout, guards stale launch generations, captures stderr, stops on exit/update, and can respawn (`:352-440`). `src/engine/connection.ts:11-74` polls readiness for 45s and injects the Basic credential; remote uses `/engine` instead. **Target:** Tauri links and starts the library on loopback, coordinates async readiness and shutdown/update in-process, and owns TLS/device auth. Do not port child spawning, stdout URL parsing, binary locks or respawn to the new runtime; test shutdown and startup generation fencing at the library/server boundary.
3. **Legacy is the live chat route.** `src/engine/actions.ts:120-200,255-352,432-541,703-728,983-1002` calls legacy SDK `session.*` and `app.agents`; `src/engine/index.tsx:148-229` hydrates legacy sessions/status/messages/provider/commands. The actual legacy HTTP handler invokes `SessionPrompt.prompt` for `/session/:id/prompt_async`, returning no content before the forked run has admitted a message (`engine/upstream/packages/opencode/src/server/routes/instance/httpapi/handlers/session.ts:295-329`). The same handler owns legacy revert, fork, command, share, permissions, message pagination (`:106-145,206-235,331-378`). Overlay code targets this path. Do not equate an HTTP 204 with durable admission.
4. **V2 exists but is not the chat driver.** The second SDK import in `src/engine/actions.ts:1-2,581-665` is used to remove provider auth. V2 permission replies are conditionally sent as raw `/api/session/:id/permission/:id/reply` for V2-originated events (`:942-969`); question replies always use legacy `/question/:id/{reply|reject}` (`:911-940`). Root control-plane move is a V2-core service behind a raw `/experimental/control-plane/move-session` POST (`:363-429`; `engine/overlays/session-move.patch:1-80`). Server assembly hosts legacy `SessionPrompt` and V2 `SessionV2` simultaneously (`engine/upstream/packages/opencode/src/server/routes/instance/httpapi/server.ts:212-305`). V2 inbox tables exist in the shared schema but ordinary Drift turns use the legacy projection. A V2 permission event does not make the entire conversation V2.
5. **Current stream:** `GET /global/event` carries `{directory,payload:{type,properties,...}}`, unlike directory-scoped `/event`. `src/engine/sse.ts:5-94` implements its own 25s inactivity watchdog, drops `sync`/heartbeat, batches only adjacent deltas in one network chunk and flushes before controls. `src/engine/index.tsx:313-460` reconnects, snapshots, and keeps session-keyed state across workspace changes. `src/engine/events.ts:32-129` accepts legacy and some V2 ask events, plus `session.next.moved`, `message.part.delta`, notices and compaction. **Target:** one WebSocket with monotonic `seq`, resume `cursor`, and a `resync` signal when replay is impossible (`AGENTS.md:35-39`; `docs/engine-rewrite.md:91-98`). Translate consumed SSE frames temporarily; conformance tests verify old reducer behavior and new ordered replay.
6. **Current gateway:** `src/runtime.ts:11-18` maps `/companion` to `/engine`, `src/backend.ts:8-29` routes host commands to authenticated `/api/invoke`, and `src-tauri/src/remote.rs:619-721` streams the request/response, strips untrusted headers, injects the engine Basic credential, and ends streams on device revocation. **Target:** remote access serves the same linked engine HTTP and WebSocket API through Tauri-owned TLS/device authentication without an engine sidecar proxy (`docs/engine-rewrite.md:149-155`). Preserve same-origin auth, request caps, command allowlist and immediate revocation across sockets (`docs/remote.md:56-91`). Browser-only dev currently stores workspaces in localStorage and deliberately cannot administer MCP (`src/state/store.ts:111-185`).

## Storage and ownership ledger

- **Two current SQLite authorities, one target.** Tauri `drift.db` has `workspace`, `session_meta` archive tombstones, `mcp_server/decision/state`, `prompt_override`, `app_setting`, `remote_access/device` (`src-tauri/src/store.rs:84-158`). It uses WAL, NORMAL and one mutexed connection. The current OpenCode database separately holds `project`, `session`, `message`, `part`, `todo`, `session_share`, `event_sequence/event`, and V2 `session_message`, `session_input`, `session_context_epoch` (`engine/upstream/packages/core/src/session/sql.ts:22-176`; `src-tauri/src/engine_db.rs:131-228`). **Target:** engine tables beside shell tables in `drift.db`, managed by a single shell/engine writer, WAL and content-addressed attachments (`AGENTS.md:43-45,59-65`; `docs/engine-rewrite.md:34-38,100-106`). The OpenCode database files are import/rollback sources only, never postcutover live authorities. The UI has additional localStorage keys for workspace order, session links, model prefs/catalog and view state (`src/engine/store.ts:144-165`, `src/state/workspaces.ts:15-17`, `src/state/provider-cache.ts:84-90`, `src/state/prefs.ts:36-53`). Preserve IDs when joining archive/link metadata to migrated sessions.
- **Source database selection is a trap.** Release preparation merges channel `opencode-master.db` into `opencode.db`; debug normally retains channel isolation, and failed release preparation falls back to channel (`src-tauri/src/engine.rs:193-255`, `src-tauri/src/engine_db.rs:17-51`). The legacy DB selector also uses channel/version flags (`engine/upstream/packages/core/src/database/database.ts:43-55`). `session_search.rs:42-51`, `storage.rs:98-115`, and `scripts/db-maintenance.ts:284` hard-code shared `opencode.db`. Record actual legacy launch paths and inventory shared/channel sources in `crates/drift-migrate`; rewrite current search/maintenance reads to use the one `drift.db` writer/read interface after cutover. Do not interpret an empty shared DB as no channel sessions.
- Existing channel merge is transactional and conservative: target session/event aggregate wins; only complete source event sequences import, children require surviving parents, incompatible optional table schemas are skipped, and writes get foreign-key checked; source is retained (`src-tauri/src/engine_db.rs:54-235,266-355`). `crates/drift-migrate` should use a versioned import ledger and ID mapping, read-only source snapshots (including WAL-consistent backup), staged transactions **through the single `drift.db` writer**, integrity checks, rollback copy and resumable batches. Quiesce the old runtime before final import; only after commit can the linked engine admit writes. Do not keep dual live writers or dual session databases as a deployment mode. Preserve legacy raw JSON/attachments and unknown parts with source provenance. Map projections and event log together or explicitly declare historical log non-replayable; avoid creating fictitious pending V2 inputs from legacy visible turns.
- Drift archives are not engine `time_archived`: `src-tauri/src/store.rs:599-625`, `src/state/workspaces.ts:168-226` implement seven-day two-phase purge of session and removed workspace tombstones. Restore of a removed directory retains identity. Engine `time_archived` also appears in `src-tauri/src/storage.rs:168-188,261-279` and the all-session listing. Migrate both flags distinctly; delete the core session and dependent blobs before clearing Drift's tombstone. Retain 404-as-confirmed-delete (`src/engine/actions.ts:716-728`), rollback of partial directory moves, and no purge of a restored workspace during a sweep (`src/state/workspaces.ts:194-215`).
- `src-tauri/src/storage.rs:1-15,231-338` currently prunes full-snapshot events, subagent/archived/orphan logs and VACUUMs the OpenCode DB; `src-tauri/src/session_search.rs:109-192` scans raw JSON in `part`. Rewrite both for the new tables using the engine/shell shared `drift.db` writer rather than a legacy-schema adapter. Decide replay retention **before** pruning: V2/event-sourced source data may require records legacy UI did not. Document whether a snapshot is sufficient to rebuild model context, diffs, audits and pending work.

## Open questions that block final cutover

1. **Historical attachments and snapshots:** confirm where file-part data URLs, binary blobs and filesystem snapshots actually reside in representative legacy DBs before choosing a blob importer; schema definitions alone do not establish retention or GC behavior. Check schema/contents with synthetic and user-approved sanitized samples, not live secret material.
2. **Credential migration:** provider auth currently lives in OpenCode `auth.json`, read indirectly by Tauri usage UI (`src-tauri/src/usage_limits.rs:308-356`). Import into the planned Rust keyring authority with headless encrypted fallback (`docs/engine-rewrite.md:26-29`); fence refresh generations and avoid token exposure to UI/logs. Validate subscription OAuth parity without invoking the legacy JS plugin in the final runtime.
3. **V2 records:** `session_input/session_message/context_epoch` may coexist with legacy projections. Determine which sessions contain meaningful pending V2 work and which events are safe to replay before importer activates them. Legacy `prompt_async` is not V2's durable inbox.
4. **Existing share links and custom plugins:** historical `share_url` may be hosted by OpenCode, while the canonical plan drops sharing (`docs/engine-rewrite.md:30-32`). Preserve the historical field for export and report links that cannot be migrated. Report `.opencode` JS plugins as unsupported; import supported data-only configuration/skills/commands where mapped, never execute arbitrary JS via Rust Hook or a compatibility loader.
5. **Cutover concurrency:** native watcher, maintenance commands and remote clients can write while import runs. A single host-level quiescence barrier must cover old process, HTTP/SSE requests, source DB WAL, policy publication and importer marker before enabling linked-library HTTP/WS admission and single `drift.db` writer.
6. **Evidence gaps and document status:** the legacy code inventory was static, not an installed-app replay. `docs/engine.md:69-85` describes newer snapshot semantics than `docs/mcp.md:55-71`'s earlier eager-close narrative; the runtime snapshot overlay refines earlier MCP reload behavior. `AGENTS.md` sets the **new** architecture, `docs/engine-rewrite.md` records its decisions and `CHECKLIST.md` records all engine milestones as pending in the current checkout. `docs/engine.md:254-345` is legacy upstream-update history, not a competing plan.
